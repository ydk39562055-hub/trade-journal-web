# 거래일지 안드로이드 앱

개인 사용을 위한 초기 설치판이다. APK 빌드와 정적 검사는 GitHub Actions에서 실행한다.
실제 Android 휴대폰 설치, 메리츠 알림 권한 허용과 수신은 아직 확인하지 못했다.
웹 화면은 기존 거래일지 사이트를 사용하므로 이후 화면 업데이트는 자동 반영된다.

## 처음 연결하기

1. APK를 휴대폰에서 받아 설치하고 **거래일지**를 연다.
2. **연결 파일 선택**에서 PC의 비공개 `자동기록_연결.json`을 선택한다.
   파일을 폰으로 가져오기 어렵다면 PC 거래일지 → 자동 기록 → 연결 관리 → 연결코드 복사로
   코드를 복사해서 폰 앱에 입력하고 **연결코드 저장**을 누른다.
   이 파일/코드는 개인 기록에 접근하는 값이므로 공개 게시하지 않는다. 토스 API 키를 넣지 않는다.
3. 설치된 메리츠 앱을 선택한다.
4. **알림 접근 설정 열기**에서 거래일지를 허용한 뒤 돌아와 **메리츠 매매 알림 수집**을 켠다.
5. 메리츠 앱에서도 체결 알림을 켠다. 이후 실제 알림을 받으면 **동기화 다시 시도**로 상태를 확인할 수 있다.
6. **거래일지 열기 → 자동 기록 → 메리츠 기록 가져오기 → 앱에서 받은 알림 불러오기**를 누른다.
7. 알림 한 건을 선택해 날짜·시장·종목·수량·가격을 확인하고 저장한다.

메리츠 알림은 선택한 메리츠 앱의 매매 관련 알림만 처리한다. 알림 접근은 사용자가 Android에서 직접 허용해야 한다.
PC가 꺼져 있어도 휴대폰 알림 수집은 폰에서 실행되지만 네트워크와 Android 백그라운드 실행 상태에 영향을 받는다.
설치 이전의 올해 거래는 **화면 캡처 선택**으로 가져온다. 날짜가 없는 알림은 체결일을 직접 확인한다.
캡처에 여러 거래가 있으면 한 건씩 확인한다. 국내주식 원화와 미국주식 달러를 구분해서 저장한다.

## 기존 일지와 함께 보기

알림 수집 연결코드와 수동 일지 동기화 코드는 서로 다르다.
기존 PC의 메모·일지·확인한 메리츠 기록까지 폰에서 보려면 폰 거래일지의 더보기 → 동기화에서
PC가 사용하는 기존 일지 동기화 코드를 연결한다. 기존 일지 코드는 공개하거나 이 저장소에 넣지 않는다.

## 동작과 검증 범위

- 선택한 앱의 새 알림을 폰의 비공개 SQLite에 중복 제거하여 보관한다.
- 알림 원문은 별도 클라우드 받은함에 모으고, 확인한 거래는 웹앱의 일지 동기화에 저장한다.
- 업로드 전에 기존 받은함을 읽고 합치며, 다시 읽어 내용이 저장됐는지 확인한다.
- 현재는 한 대의 휴대폰을 주 수집기로 사용한다. 동시 여러 폰의 완전한 쓰기 직렬화는 제공하지 않는다.
- 재시도 작업은 최소 15분 주기이며 새 알림이 오면 즉시 업로드를 요청한다.
- 알림 수신시각을 실제 체결일로 임의 바꾸지 않는다. 최종 거래는 2026-01-01 한국 시간부터 허용한다.
- 주문/매도 API를 호출하지 않는다. APK에는 증권사 인증정보와 개인 연결코드가 없다.
- APK는 개인 테스트용 debug 서명이다. 스토어 배포판이나 실제 기기 검증을 마친 정식판은 아니다.
- 업데이트용 debug 서명 키는 CI 캐시에 보관한다. 캐시가 만료되면 같은 서명으로 업데이트할 수 없으므로
  정식 배포 전 별도 장기 서명 키 관리가 필요하다. 재설치 전에는 기존 일지를 동기화/백업한다.

빌드: Java 17, Gradle 8.11.1, Android Gradle Plugin 8.9.2, compile/target SDK 35, Android 8 이상.
GitHub Actions의 `build-android-companion` 작업에서 APK와 Android lint, APK 서명을 확인한다.
