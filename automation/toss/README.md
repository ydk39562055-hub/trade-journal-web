# 토스 거래일지 자동 수집

2026-09-05 실제 계좌 조회 검증: 계좌 1개, API 주문 1,232건,
체결이 있는 주문 1,020건(USD 주문 1,014건), 현재 보유 종목 3개.
이 수치는 조회 당시의 결과이며 이후 거래에 따라 바뀐다.
조회는 사용자 바탕화면 ap.txt의 키를 읽어 토스 공식 API에만 인증했다.
키·토큰·실제 계좌 이력은 이 저장소에 저장하지 않는다.

## 완료한 범위와 남은 단계

- 공식 인증, 계좌 목록, 주문 전체 페이지, 미체결 주문, 주문 상세, 보유 내역 조회.
- 수량·가격·비용의 소수 문자열과 큰 계좌 ID를 원래 정밀도로 보존.
- 주문별 누적 체결을 고유 ID로 교체하여 재수집 시 중복을 방지.
- 취소된 주문의 부분 체결도 보존하고, 조회 창에서 사라진 과거 주문은 삭제하지 않음.
- 전체 조회 완료 후 파일 교체. 오류 시 직전 이력 유지, 상태 파일에 실패 기록.
- 5분 간격 순차 수집, 토큰 재발급, 실패 시 대기 연장, 동시 프로세스 실행 차단.
- 서버 재부팅 시 시작할 systemd 서비스 템플릿.

2026-09-06 업데이트: 사용자 선택으로 유료 서버 대신 Windows 로그인 자동 실행을 설치했다.
별도 클라우드 기록과 앱 자동 기록 탭 연결을 검증했다. 앱에는 2026년 체결 178건만 반영한다.
현재 설치/사용법은 상위 [PC 자동 수집 안내](../README.md)를 따른다.
`cloudPublished: false`는 로컬 수집만 된 상태이고 true는 클라우드 재조회 검증까지 통과한 상태다.
PC에서 `--watch`로 실행하므로 PC를 끄거나 절전하면 멈춘다.

## 자료 해석

`executions` 한 행은 주문 한 건의 누적 체결 결과다. 개별 체결 횟수와 다르다.
체결 완료 시각은 마지막 체결 시각이다. 분할 매수·매도를 가상의 개별 체결로 나누지 않는다.
API 날짜 필터는 주문 접수일 기준이라 사용하지 않고 전체 이용 가능 이력을 순회한다.
증권사의 API 제공 기간 이전 거래까지 확보했다는 의미는 아니다.
같은 주문이 페이지 경계나 OPEN/CLOSED에 중복되면 마지막에 주문 상세를 다시 조회한다.
매매 중 여러 조회 결과는 단일 시점 거래소 스냅샷이 아니므로 다음 수집 때 다시 대조한다.

체결 대금은 손익이 아니다. 실현손익은 `null / unreconciled`로 두었다.
매입 원가·주식 분할·입출고·부분 매도와 수수료를 대조하기 전 일지 통계에 자동 합산하지 않는다.
미정 수수료/세금은 0으로 바꾸지 않는다. 브로커 사실과 사용자의 메모/사진은 분리해야 한다.
기존 `sync_push`는 일지 전체를 덮어쓰므로 수집기가 호출하면 안 된다.

## 실행

Node.js 24 이상. 실행 설정은 `.env.example`을 참고해 **저장소 밖**에 만든다.
바탕화면 메모장을 사용할 때는 `TOSS_NOTE_PATH`를 지정한다.
서버에서는 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`을 외부 비밀 설정 파일에 둔다.
서버와 개발 PC를 같은 키로 동시에 수집하지 않는다. 토스는 새 토큰 발급 시 기존 토큰을 무효화한다.

```text
node --env-file=<비공개설정파일> automation/toss/collect.mjs
node --env-file=<비공개설정파일> automation/toss/collect.mjs --watch
node --test automation/toss/client.test.mjs automation/toss/history.test.mjs automation/private-store.test.mjs
```

`TJ_PRIVATE_DATA_DIR`는 절대 경로이며 공개 저장소 밖이어야 한다.
`toss-snapshot.json`에 원본과 정규화된 사실을 함께 보관한다.
`toss-status.json`은 최근 상태와 수집 건수이며, 오류 상태에서도 직전 성공 시각을 보존한다.
SQLite 파일은 단일 실행 잠금용이며 프로세스 종료 시 운영체제가 잠금을 해제한다.

세금·카드 환전 비용은 별도이며 유료 백업·추가 볼륨은 이 제안에 포함하지 않는다.
공식 가격: https://www.digitalocean.com/pricing/droplets
서버를 파괴하고 다시 만들면 IP가 바뀔 수 있으므로 토스 허용 IP를 다시 확인해야 한다.

유료 생성 전 사용자 비용 승인이 필요하다. 승인 후 서버 계정/결제는 사용자가 준비하고,
서버의 실제 IPv4를 토스 API 설정에 등록한다. 키는 HTTPS/SSH를 통해 서버 비밀 파일로만 옮긴다.
최종 IP·계정·사용 가능한 지역·세금·결제 화면을 확인하기 전에는 서버 생성을 실행하지 않는다.

배포 시 전용 비로그인 OS 사용자 `trade-journal`, 코드 `/opt/trade-journal`,
비밀 설정 `/etc/trade-journal/toss.env`(root 소유, 0600),
실제 데이터 `/var/lib/trade-journal`을 사용한다. Node 24의 실제 실행 경로를 확인한 뒤
`trade-journal-toss.service`를 설치한다. 템플릿 커밋만으로 서비스가 설치되지는 않는다.

다음 구현은 기존 Supabase에 수집 데이터 전용 저장/조회 통로를 추가하는 것이다.
읽기 코드와 서버 쓰기 권한을 분리하고, 민감한 원본 전체를 공개 정적 파일로 제공하지 않는다.
